# ADR-0009: GitHub Actions Runtime Currency (Node 24 Action Majors)

## Status

**Accepted**. Giovanni Fiore accepted this ADR on 2026-09-04, approving the bump of
`actions/checkout` and `actions/setup-node` to `@v5` across the repository
workflows, the canonical generated governance workflow, and the
`ci-cd-and-automation` skill examples.

## Context

GitHub is deprecating the Node.js 20 runtime for GitHub Actions. Runners now force
actions that target Node 20 to execute on Node 24 and emit a deprecation warning;
the warning was observed in the `v0.5.0` publish run for `actions/checkout@v4` and
`actions/setup-node@v4`. When Node 20 support is removed, the forced fallback ends
and these pins fail.

The affected pins live in three distinct layers of the kit:

1. **Repository infrastructure** — `.github/workflows/ci.yml` and
   `.github/workflows/publish.yml` (the kit's own pipelines).
2. **Canonical kernel** — the governance workflow generated by
   `ciEnforcementWorkflow()` in `plugins/agentic-repo/scripts/lib/plan.mjs`, which
   is projected into every repository initialized with `--enforce ci`.
3. **Advisory skill** — example workflows in
   `plugins/agentic-repo/skills/ci-cd-and-automation/SKILL.md`.

Because layer 2 is policy-bearing canonical surface, stale action majors would be
propagated to every generated repository. This makes the change architecturally
relevant rather than purely repo-local maintenance, and it engages the portability
invariant that runtime adapters must not drift from supported platforms.

No product scope or user-facing outcome changes, so a PRD is not required.

## Decision

1. Bump `actions/checkout` and `actions/setup-node` from `@v4` to `@v5` — the
   first major line whose action runtime is Node 24 — across all three layers:
   the repository infrastructure workflows, the canonical generated governance
   workflow in `plan.mjs`, and the `ci-cd-and-automation` skill examples.
2. Pin to the floating major tag `@v5` (not a commit SHA), consistent with the
   kit's existing `@v4` convention, preserving readability and matching current
   generated output.
3. Leave `node-version: 24` in the generated governance workflow unchanged; only
   the action majors move.
4. Ship as a patch release (`0.5.1`): mechanical, non-breaking, no interface or
   policy change.

## Consequences

### Positive

- **POS-001**: Clears the Node 20 deprecation warning in the kit's own pipelines
  and in every `--enforce ci` repository generated from the kernel.
- **POS-002**: Keeps the canonical projection current with the supported Actions
  runtime, honoring the "adapters must not drift" portability invariant.
- **POS-003**: Minimal, mechanical change with no policy, interface, or behavior
  change, keeping the validation surface small.

### Negative

- **NEG-001**: Floating `@v5` tags can absorb action-side changes within the major;
  mitigated by Actions semver stability guarantees and by matching the kit's
  pre-existing floating-tag convention.
- **NEG-002**: Choosing `@v5` defers evaluation of `checkout@v6/v7` (safer
  `pull_request_target` defaults) and `setup-node@v6/v7` (ESM, npm-only caching);
  a future currency pass may revisit these majors.
- **NEG-003**: The canonical generator and the advisory skill examples must be
  updated and validated together to prevent divergence between documented and
  generated output.

## Alternatives Considered

### Pin to the latest majors (checkout@v7, setup-node@v7)

- **ALT-001**: **Description**: Adopt the newest major lines instead of `@v5`.
- **ALT-002**: **Rejection Reason**: Larger behavioral delta (ESM migration,
  npm-only automatic caching, stricter `pull_request_target` defaults) with no
  benefit for these caching-free, `pull_request`-based workflows. `@v5` is the
  minimal fix that resolves the deprecation.

### Pin to immutable commit SHAs

- **ALT-003**: **Description**: Replace version tags with pinned commit SHAs for
  supply-chain hardening.
- **ALT-004**: **Rejection Reason**: Diverges from the kit's readable floating-tag
  convention and raises maintenance cost without a stated hardening requirement;
  SHA pinning belongs in a dedicated supply-chain ADR if pursued.

### Do nothing / suppress the warning

- **ALT-005**: **Description**: Leave `@v4` and ignore the deprecation notice.
- **ALT-006**: **Rejection Reason**: The warning becomes a hard failure once Node
  20 support is removed, and stale majors would keep propagating to generated
  repositories.

## Implementation Notes

- **IMP-001**: Update `ci.yml`, `publish.yml`, `plan.mjs`
  (`ciEnforcementWorkflow`), and the `ci-cd-and-automation` skill examples in a
  single vertical slice.
- **IMP-002**: Regenerate a clean temporary repository with `--enforce ci` and
  confirm the projected `governance.yml` renders `@v5`; run `npm run validate`
  (tests, skills, plugin) and verify generated relative links resolve.
- **IMP-003**: Record the change in `CHANGELOG.md` (`0.5.1`) and the wiki log;
  success criterion is a green CI run with no Node 20 deprecation annotation.
