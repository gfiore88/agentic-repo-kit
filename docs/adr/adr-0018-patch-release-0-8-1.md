# ADR-0018: Patch Release 0.8.1

## Status

**Accepted** by Giovanni Fiore on 2026-11-13. He replied "si approvo" ("yes, I
approve") to the request to accept ADR-0018 and publish 0.8.1.

## Context

[ADR-0017](adr-0017-version-pinned-projected-invocation-and-tolerant-frontmatter-parsing.md)
is merged on `main`. Repositories generated by 0.8.0 still carry unpinned CLI
instructions, so a stale global install can answer them; a global 0.6.0 did exactly
that during the 0.8.0 publication check. Generated hooks and CI run the pinned
verifier, so the CRLF and YAML-comment parsing fixes reach enforced repositories
only through a release followed by `update`.

The changes fix defects in existing behavior. No CLI command or option is added or
removed.

## Decision

1. Release the ADR-0017 work as **0.8.1** (SemVer patch).
2. Follow [the release guide](../releasing.md): move `[Unreleased]` to `[0.8.1]` in
   `CHANGELOG.md`, run `npm run validate`, run
   `npm version patch -m "chore(release): %s"` (the `version` script syncs
   `plugin.json`), push `main` and tag `v0.8.1`, and publish the GitHub release so
   `publish.yml` publishes through Trusted Publishing.
3. No file under `.github/workflows/**` changes, so the push needs no `workflow`
   token scope.

## Consequences

### Positive

- **POS-001**: After `update`, generated instructions run 0.8.1 whatever is
  installed globally.
- **POS-002**: CRLF checkouts and commented frontmatter stop failing pinned hooks
  and CI after `update`.

### Negative

- **NEG-001**: Each `update` rewrites the files that carry the pin. As designed in
  ADR-0013, files that a user modified are reported as conflicts.
- **NEG-002**: Existing copies of the user-owned `docs/adr/README.md` keep their
  unpinned wording until the user deletes them and reruns `update`.

## Alternatives Considered

### Minor release 0.9.0

- **ALT-001**: **Description**: Ship as a minor release because generated content
  changes.
- **ALT-002**: **Rejection Reason**: No feature or option is added; the changes fix
  the invocation defect and two parsing defects.

## Implementation Notes

- **IMP-002**: Record the release in `docs/wiki/log.md`.
